# Rahma — Flutter Setup

**Audience:** developer on a workstation with Flutter SDK 3.24+.

## What's already in the repo

- `apps/mobile/pubspec.yaml`
- `apps/mobile/analysis_options.yaml`
- `apps/mobile/.gitignore`
- `apps/mobile/lib/{main,app,config}.dart`
- `apps/mobile/lib/screens/*.dart` (9 screens)
- `apps/mobile/test/config_test.dart`

The Android / iOS native directories are NOT committed (per
`apps/mobile/.gitignore`). They are generated locally by:

```bash
cd apps/mobile
flutter create .
```

Flutter creates `android/`, `ios/`, `linux/`, `macos/`, `web/`,
`windows/` for the platforms enabled in the local install. For Rahma
we use only `android/` + `ios/`; the others can be removed.

## First-time setup

```bash
cd apps/mobile

# 1. Generate native shells (per-workstation; never committed).
flutter create . --platforms=android,ios

# 2. Install Dart deps.
flutter pub get

# 3. Run analyzer + tests.
flutter analyze
flutter test
```

## Run the app

```bash
# On a connected Android device / emulator:
flutter run -d android \
  --dart-define=RAHMA_API_BASE=https://api.<final-rahma-domain> \
  --dart-define=RAHMA_BUILD_FLAVOR=internal-test

# On iOS simulator:
flutter run -d ios \
  --dart-define=RAHMA_API_BASE=https://api.<final-rahma-domain> \
  --dart-define=RAHMA_BUILD_FLAVOR=internal-test
```

If `--dart-define=RAHMA_API_BASE` is omitted, the app starts but every
screen renders the "service not configured" Arabic copy — by design.

## Release build (when CI / signing is wired)

```bash
# Android AAB:
flutter build appbundle --release \
  --dart-define=RAHMA_API_BASE=https://api.<final-rahma-domain> \
  --dart-define=RAHMA_BUILD_FLAVOR=release

# iOS IPA:
flutter build ipa --release \
  --dart-define=RAHMA_API_BASE=https://api.<final-rahma-domain> \
  --dart-define=RAHMA_BUILD_FLAVOR=release
```

## Hard rules

- NEVER commit `android/` or `ios/`. They are regenerated by every
  workstation.
- NEVER commit signing keystores (`*.jks`, `*.keystore`,
  `*.mobileprovision`, `*.p8`, `*.p12`, `*.cer`).
- NEVER hardcode the API hostname in any `.dart` file. Always read from
  `RahmaConfig.apiBase`.
- NEVER ship a build with `RAHMA_API_BASE=api.rahma.example` or any
  OrdinoxAI domain.
